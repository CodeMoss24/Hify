>    - `code === 200` → 自动返回 `data` 字段（解包），让业务代码直接用数据
>    - `code !== 200` → 用 Element Plus 的 `ElMessage.error` 提示 `message`，然后 reject
> 3. 网络异常时同样用 `ElMessage.error` 提示“网络异常”，然后 reject
> 4. 导出 `get`、`post`、`put`、`del` 四个方法

**目的：** 前后端规范体系的结合点。后端定了统一响应格式 `{code, message, data}`，前端 axios 拦截器根据 `code` 自动解包——业务代码直接用 `data`，不需要每次手动 `.data` 和 `if (code !== 200)`。几十个接口累积下来，代码干净很多。

**步骤24：前后端联通验证——发现问题与修复**

**问题1：路由和组件不匹配**
Claude 的诊断：健康检查代码写在 `ProviderList.vue` 里，但路由指向的是 `ProviderView.vue`，所以健康检查逻辑从未执行。修复方案：把健康检查代码合并到 `ProviderView.vue`。

**问题2：请求路径 404**
- 浏览器控制台报 `Request failed with status code 404`
- 根因：Vite 代理配置缺少 `rewrite` 规则，`/api` 前缀被一起转发到后端，后端路由 `/v1/health` 匹配不上 `/api/v1/health`

**提示词（修复 Vite 代理）：**
> 请在我的 `vite.config.ts` 的 proxy 配置里加上 rewrite 规则，把 `/api` 前缀在转发到后端前去掉。直接帮我改。

**问题3：前后端格式不匹配**
- 后端返回 `{"status":"ok"}`，前端判断 `res.code === 200`
- 缺少 `code` 字段 → axios 误判为失败 → 显示红色“后端未连接”
- 修复：后端健康检查改用 `ApiResponse.ok(data="Hify is running")`，返回 `{"code":200,"message":"success","data":"Hify is running"}`

**成功标准：** 浏览器打开 `http://localhost:5173`，点左侧“模型管理”菜单，右侧显示绿色的 **“后端已连接：Hify is running”**。
