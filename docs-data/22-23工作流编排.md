### 3. 实现核心循环（线性执行版本）

**做什么：** 搭好执行引擎最简化版本——只支持从 START 沿无条件连线走到 END。包括更新数据模型（Agent 加 workflow_id、新建两张执行记录表）、ExecutionContext 类、核心 while 循环。

**目的：** 先跑通骨架。验证 Context 能在节点间正确传数据、执行记录能正常落库。

**提示词（Python FastAPI 版本）：**

> 实现 Hify 工作流执行引擎的核心骨架。技术栈：Python FastAPI + SQLAlchemy。
>
> **1. 更新数据模型：**
> - 给 `tb_agent` 表加 `workflow_id BIGINT DEFAULT NULL` 字段
> - 新建 `tb_workflow_run`（工作流执行记录，字段：workflow_id、status、input、output、error_message、elapsed_ms、started_at、finished_at）和 `tb_workflow_node_run`（节点执行记录，字段：workflow_run_id、node_key、node_type、status、input_data、output_data、error_message、elapsed_ms、started_at、finished_at）
>
> **2. 创建 `app/workflow/context.py`（ExecutionContext）：**
> - 内部用 dict 存变量，保持写入顺序
> - 构造时传入 `user_message`，预写入为 `"start.userMessage"`
> - `set(node_key, var_name, value)`：写入，key 格式为 `"node_key.var_name"`
> - `resolve(template) -> str`：把模板里的 `{{node_key.var_name}}` 替换为实际值
> - `get_all() -> dict`：返回所有变量的只读视图，用于执行记录落库
>
> **3. 创建 `app/workflow/engine.py`（WorkflowEngine 核心循环）：**
> - `execute(workflow_id, user_message, db)` 方法，先只实现线性执行：
>   1. 从数据库加载节点和连线，构建 `node_map` 和 `edge_map`
>   2. 创建 `WorkflowRun` 记录（status=RUNNING）
>   3. 创建 `ExecutionContext`，预写入 `user_message`
>   4. 找到 START 节点，进入 while 循环
>   5. LLM 节点：读 config 里的 `prompt`，`ctx.resolve()` 替换变量，调 Adapter 调 LLM，结果 `ctx.set(node_key, output_variable, response_text)`
>   6. `find_next`：找出边中 `condition` 为空的边
>   7. END 节点：结束循环，更新 `WorkflowRun`（status=SUCCESS）
>   8. 50 步超时保护
>
> **4. 更新 Agent Schema 和 Service**：`AgentCreate`、`AgentUpdate`、`AgentResponse` 各新增 `workflow_id: Optional[int] = Field(default=None)`。`create_agent` 和 `update_agent` 同步处理。
>
> **约束：** 先只实现线性执行，条件分支下一步加。遵循 CLAUDE.md 代码组织规范。不引入新的异步机制。

### 4. 加条件分支（CONDITION 节点）

**做什么：** 在已经跑通的线性执行引擎上，加入 CONDITION 节点支持。根据前面节点的输出匹配连线条件，走对应分支。

**目的：** 让工作流能根据用户输入的不同，自动走不同的处理路径。这是工作流区别于“一个 Prompt 走到底”的核心能力。

**提示词（Python FastAPI 版本）：**

> 基于已经跑通的线性执行引擎，现在加入条件分支（CONDITION 节点）支持。
>
> **1. 在 `app/workflow/engine.py` 里实现 CONDITION 节点的执行逻辑：**
> - 在主循环里加 `elif current_node.node_type == "CONDITION":` 分支
> - 读节点 config 里的 `expression` 字段，用 `ctx.resolve()` 替换变量得到实际值
> - 将结果写入 ctx：`ctx.set(node_key, "result", resolved_value)`
>
> **2. 修改 `_find_next_node` 方法：**
> - 如果是 CONDITION 节点：从 ctx 取 `{node_key}.result`，遍历出边找 `edge.condition` 匹配的边。没匹配到走第一条 `condition` 为空的出边作为默认
> - 非 CONDITION 节点：保持原逻辑，只走 `condition` 为空的出边
>
> **约束：** 只改 `_find_next_node` 和主循环 CONDITION 分支，不改已有线性执行路径。
